# PR 10 — проверка многосегментной декларативной цепи (эксперимент)
Дата: 2026-11-13.

## Что реализовано
- terminal-path-v2.js: BFS только по явно объявленным wires, с контролем роли проводника, отсутствия подмены клемм и без автоматической проводимости через контакт аппарата.
- endpoint-bridge-v1.js: новый необязательный параметр `{allowDeclaredMultiSegment:true}`. По умолчанию поведение v1 **не меняется**: отсутствие прямого провода блокирует связь.
- При найденном многосегментном пути возвращается `MULTI_SEGMENT_DECLARED_ONLY` с уровнем UNKNOWN. Это не монтажный PASS.
- Добавлены самостоятельные и интеграционные тесты (10 сценариев). Запуск CI/Node ещё не подтверждён.

## Ограничения и приёмка
1. Топология основана на пользовательских декларациях; производитель, клеммные перемычки, N/PE и реальные соединения не удостоверены.
2. Нет разрешения на инженерное проектирование или монтаж; `engineeringApproved=false`.
3. Нельзя включать режим в UI и сливать PR, пока не проверены все Node-тесты, исходный Python-архив v4.14, крайние случаи и правила терминальных блоков.
4. Текущий алгоритм трактует все явно объявленные wire-сегменты как рёбра, но не учитывает допустимую кратность проводов в зажимах и достоверность клеммных перемычек.
5. Глобально неверно объявленный провод может блокировать поиск даже другой цепи: это намеренно консервативно, но требует UX-объяснения.
