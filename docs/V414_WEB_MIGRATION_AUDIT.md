Сохранить GitHub Pages / статические HTML, CSS и JavaScript без обязательного Python-сервера. Переносить проверенную функциональность, а не копировать Python в рабочий браузерный проект. **Полный архив v4.14 восстановлен** из библиотеки файлов: electropanel_core_v4.14.zip (172 файла). Локально выполнено 883 Python-теста: OK. Это проверка регрессии, не нормативная сертификация или гарантия совместимости с Web.

## Барьеры к объединению в `main`
1. Найти и идентифицировать **реальные исходники v4.14** (либо явно учесть отсутствие), не смешивая с отдельной веткой 0.1.
2. Сохранить безопасный откат и провести полный `node --check`, `node --test tests/*.test.js`, проверить CI и вручную главные сценарии браузера/JSON.
3. Для каждого перенесённого нормативного расчёта: источник/редакция нормы, область применения, тестовые данные, ожидаемое значение и статус неопределённости.
4. Не переводить `PRELIMINARY_PASS` в статус допуска проекта; не допускать молчаливого сброса устаревших расчётов.
5. Полный перенос v4.14 пока **не подтверждён**; PR #1 остаётся draft до проверки.

## Порядок реализации крупными блоками
1. Единая модель расчётных входов/выходов, перенос проверок перегрузки и токов КЗ с независимыми тестами.
2. Сопоставление электрических связей с проверками контактов, нейтрали, защитного проводника, полноты исходных данных.
3. Паспортный каталог реальных серий, геометрия и качественные фасады; визуал не влияет на инженерное решение.
4. Сквозные браузерные сценарии, миграции старых JSON, CI, проверка GitHub Pages и только затем объединение.

**Статус этого документа:** зафиксированная карта совместимости на основании доступных материалов. Это НЕ утверждение об успешном переносе или проверке старого полного ядра.

## Второй совместимый перенос: overload guard v3.0
- Из оригинального electropanel/overload_guard_v30.py перенесены в overload-v30.js: явные Ib/In/baseIz/I2, 1..32 именованных коэффициента, отдельный статус арифметики, десять доказательных реквизитов и постоянный статус UNVERIFIED.
- В JS выбран BigInt-декодер десятичных чисел и научной записи, а не обычная float-арифметика. На старых Python-сценариях совпало решение PASS/FAIL/UNKNOWN для 12/16/20/28, 12/16/20/29, 12/16/20/30, факторов >1, пропусков, булевых, 1e308 и 1e-600.
- Web-форма для этого расчёта свёрнута по умолчанию, данные хранятся независимо в overloadV30; существующий overloadInput не переписывается.
- Точный формат строк Decimal может отличаться (например, 29 против 29.00); сравниваются математические значения и диагнозы, а не представление нулей.
- Перед публикацией необходим полный набор Node-тестов и испытания интерфейса; даже арифметически PASS не подтверждает монтажные условия.

## Блок переноса TT / УЗО v4.5 — 13.11.2026

- Из оригинального `electropanel/tt_cable_v45.py` перенесена **только** самостоятельная функция ограниченной проверки TT/RCD — `epTTScreenV45` (чистый JavaScript, файл `tt-screen-v45.js`).
- Проверяются явно заданные RA, IΔn, UL (25/50 В), время отключения и полнота декларативных предпосылок. Неизвестные сети, генератор, специальные условия и неподтверждённые исходные данные приводят к `OUT_OF_SCOPE` / `UNKNOWN`, а не к фиктивному PASS.
- Для совпадения с исходным Python реализовано десятичное округление `ROUND_HALF_EVEN` до 34 значащих цифр, включая пограничные значения сопротивления RA. Тесты сверяют результаты с `tests/test_v45.py` старого архива.
- Поле `ttContext` хранится на уровне проекта, отдельно от отходящих линий, и строго проверяется при импорте JSON. Система заземления проекта, отличная от TT, вызывает отдельный конфликт в инженерном аудите и статус `OUT_OF_SCOPE` в интерфейсе.
- Результат `PASS` подтверждает только арифметическое соответствие **введённых пользователем** чисел. Даже в этом случае `ready_for_design=false` и `ready_for_installation=false`, реальность измерений, паспорта, условия испытаний и применимые нормы программа не удостоверяет.
- **Не перенесены этим блоком:** `cable_provenance_v45`, связанный `bound_tt_review_v45`, аппаратная схема/автоматическое отключение во всех системах, полный расчёт КЗ и выбор кабеля. Полное объединение v4.14 остаётся открытой задачей.
