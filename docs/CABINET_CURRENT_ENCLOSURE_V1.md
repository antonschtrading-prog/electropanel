# Сопоставление текущего щита с корпусами — версия 1

Самостоятельная проверка в разделе «Компоновка» принимает несколько корпусов по полезным внутренним размерам и сравнивает их с ТЕКУЩИМ расположением аппаратов. Межрядная оптимизация не требуется, состав аппаратов и электрическая модель не меняются.

Реализованы: независимое построение текущего плана DIN через epDraftBoardPlanV1; снятие габаритов по выбранным артикулам; расчёт предварительных требований к корпусу; сопоставление ширины, высоты, глубины и числа реек; отдельная аналитика дефицитов; список недостающих сведений; CSV исходных проверок, CSV запроса поставщику и JSON-протокол.

Инженерные статусы:
- PRELIMINARY_MATCH — известные размеры и количество реек не меньше расчётных условных требований, не означает сертифицированный монтажный результат.
- UNVERIFIED — данных не хватает (габариты аппаратов, полезная ширина, высота, глубина или число DIN-реек).
- REJECTED — по уже известным данным корпус недостаточен, даже при наличии других неизвестных параметров.
- BLOCKED — ошибка исходной модели или невозможность корректно выполнить аудит.

Размеры корпуса — только явно введённые полезные внутренние размеры, а не внешние паспортные габариты. Модульная ширина, высота между рядами и глубинные припуски условные. Реальные DIN-крепления, посадочные размеры, клеммы, двери, тепловые требования и кабельные трассы требуют отдельной проверки у изготовителя.

Экспорт блокируется, если после предварительного расчёта меняется проект либо список кандидатов. Ведомость поставщику экранирует CSV-формулы, содержит недостающие размеры и проверяемые геометрические дефициты. Завершённая инженерная совместимость НИГДЕ не утверждается.

Тесты: tests/cabinet-current-enclosure-v1.test.js; сквозной сценарий Chromium в scripts/browser-integration.cjs. Только успешный CI на конкретном коммите подтверждает завершённость программных проверок.
