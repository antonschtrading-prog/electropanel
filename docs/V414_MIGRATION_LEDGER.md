## Критические незакрытые направления
1. Подтверждение применимости норм и официальных редакций; v3.8/v3.9 хранят только небольшие числа из вторичных публичных воспроизведений. Источник официальных значений не удостоверен.
2. `manufacturer_ratings_v36`, `verified_product_seed_v35`, `catalog_import`: спецификации реальных артикулов и CAD/фото по конкретным сериям изготовителей. Три текущих пробных записи — не полная база оборудования.
3. `circuit_binding_v41`, `circuit_assurance_v42`, `reference_circuits_v40`, `line_impedance_v44` bound-path: полная привязка электрических расчётов к действительному топологическому графу цепей и источнику.
4. `engineering`, `wiring_audit`, `visual_editor_v410`, `branch_editor_v49`: физические контактные соединения, нейтраль после УЗО, PE, клеммы, проверка схемы и достоверная сборка.
5. `coordination`, `verification`, `safety_audit_v29`, `project_workflow_v46`: селективность, полные токи КЗ, отключение в требуемые сроки, тепловой режим, электрическая безопасность.
6. Совпадение численных проверок не доказывает отсутствие пограничных расхождений: в v4.3/v4.4 применён консервативный `UNKNOWN` вблизи порога из-за IEEE754; математически эквивалентный `Decimal`-расчёт здесь не утверждается.
7. Полный браузерный и нормативный выпуск проектной документации не подтверждён; без независимой экспертной сверки готовность остаётся `false`.

Слияние с `main` — техническая публикация этапа, а не подтверждение полной инженерной программы.

## 2026-11-13 — прямая миграция `wiring_audit.py` v1.8

В Web добавлен `wiring-audit-v18.js`: независимая проверка явно указанных клемм, проводников, внутренних контактов аппаратов, источников и нагрузок. В отличие от условного графа Web не предполагает проводимость через неизвестный аппарат. По 160 детерминированным вариантам старого Python и браузерного JavaScript совпадают статусы, коды, диагностические детали, счётчики и канонический SHA-256 (при доступном WebCrypto), **160/160**.

В «Документах» схема терминалов сохраняется отдельно в `wiringModelV18`, восстанавливается после экспорта/импорта и включена в аудит. Ошибки блокируют готовность черновика; найденная непрерывность остаётся исключительно заявлением об условной схеме. Автоматического сопоставления идентификаторов устройств и контактов с 3D/2D расположением щита **ещё нет** — это отдельная критическая задача. Часть старого v4.14 перенесена, но полное объединение проекта не завершено.

## Дополнение: device_audit.py v1.9 → Web

Добавлен `device-audit-v19.js` с проверкой числа и одновременного состояния полюсов аппаратов, запретом PE через коммутируемый контакт, распределением нейтральных клемм по зонам и обнаружением мостов между различными зонами N. Исходные сведения о производителе маркируются как `UNVERIFIED`; наличие ссылки и SHA-256 само по себе не доказывает подлинность документа. Сохранение модели `deviceModelV19` в проектном JSON не подменяет реальную топологию конструктора. Если сохранена и `wiringModelV18`, программа сравнивает общие клеммы, провода и контакты; расхождения становятся блокирующими ошибками. Метаданные связанных полюсов `gang_id` в модели проводов не требуются.

Реальный независимый контроль: исходные тестовые сценарии `test_device_audit.py`, базовый SHA-256 эталона из Python и браузерный сценарий с конфликтом состояний и PE. **Модуль перенесён как консервативная проверка деклараций, а не готовый механизм автоматической сборки щита.**

## 2026-11-13: привязка графического конструктора и электрической модели

Новый браузерный слой `board-binding-v1.js` использует **действительные устойчивые ID аппаратов** из `branchDevices` и `sharedDevices` (тех же сущностей, которыми управляется DIN-компоновка). Пользователь вручную сопоставляет их с `deviceModelV19.devices`. Сохраняется `boardBindingsV1` с двумя ID и контрольными снимками текущего аппарата и модели (тип, полюса, названия терминалов и роли). Изменение артикула, ширины, названия, фазы, числа полюсов или терминалов **инвалидирует** ранее заявленную привязку; старые связи никогда не переназначаются молча.

Дополнительно проверяются паспортные **заявленные** полюса при наличии точного каталожного артикула, несовместимость фаз терминалов, объявленная полюсность групповых УЗО 2P/4P, отсутствие/повтор связей и непокрытые устройства. Ошибки попадают в общий аудит; неполное соответствие блокирует готовность черновика. На DIN-изображении теперь виден компактный индикатор ручной связи и устаревшей привязки.

**Ограничения:** это проверка соответствия двух информационных моделей по ID, а не автоматическое получение схемы контактов из изображения, не база достоверных физических клемм производителя и не гарантия, что реальные N/PE/фазные проводники подключены правильно. `engineeringApproved=false` при любом результате. Функциональная преемственность всех 51 модулей v4.14 по-прежнему не доказана.
