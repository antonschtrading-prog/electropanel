# Пять глав интеграции диагностики · 13 ноября 2026

## 1. Электрическая топология
`terminal-path-v2.js` и `topology-batch-audit-v1.js` проверяют только явно заявленные провода и клеммы. Проводимость через контакты устройств не подразумевается. Отсутствие цепи — блокировка; неизвестная информация — UNKNOWN.

## 2. Согласованность модели
`engineering-gate-v1.js` агрегирует диагностику компоновки, топологии и соответствия моделей устройств/проводов. При исключении компонента результат блокируется. Ни один результат не означает инженерного допуска.

## 3. Визуальный конструктор
В `view-board` добавлен диагностический раздел, обновляемый через общий `render()` при изменениях проекта. Панель доступна только в feature-ветке до принятия PR.

## 4. Выгрузка результатов
Кнопка «Экспорт JSON» сохраняет отдельный файл с суффиксом `_engineering_diagnostics_DRAFT.json`. Проект не меняется; в отчёте всегда `engineeringApproved:false`, `ready_for_installation:false`.

## 5. Проверка и критерии объединения
Новые регрессионные тесты проверяют наличие всех скриптов, порядок загрузки, размещение панели, обновление через render, экспорт и недопустимость выдачи допуска. CI должен пройти на последнем коммите PR. До объединения также нужны ручная браузерная проверка и независимая сверка расчётов с исходным Python v4.14 (архив пока не подтверждён как доступный).

### Известные ограничения
- Реальная клеммная схема производителя, нагрев, КЗ, селективность и нормативная пригодность не подтверждены.
- Внутренние соединения аппаратов не считаются проводниками без отдельной модели.
- Каталог содержит демонстрационные записи; реальная графика аппаратов и проверенные datasheet-поля — отдельный блок.

## Дополнение: каталог производителей
`catalog-evidence-audit-v1.js` добавляет отдельный статус по артикулу, серии, производителю и ссылке на источник. Даже совпавший артикул не подтверждает клеммы, габариты или монтажную пригодность. Диагностика каталога подключена к общему инженерному отчёту; данные производителя требуют отдельной верификации.
