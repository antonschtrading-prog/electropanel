# DIN-каталог: этап устранения пробелов

## Выполнено
- 11 типов оборудования в отдельной схеме с проверкой идентичности, источников и габаритов.
- Преобразование заявленной ширины в целое число 18-мм мест на DIN-рейке. Это консервативная **оценка занимаемого места**, не подтверждение совместимости с конкретным корпусом или стандартом модульности.
- Проверка дубликатов, отсутствующих устройств и несоответствия ширины аппарата размещению.
- Проект замены артикула синхронно выдаёт обновлённые геометрию, ширину, серию, производителя и визуальное представление **без автоматического изменения проекта**.
- Общий инженерный отчёт показывает замечания размещения. Статус допуска всегда отрицательный.

## Незакрытые пробелы
1. Исходный `catalog.js` хранит старые записи и не содержит полных паспортных размеров и проверенной модели фасада. Не считать их автоматически записями VERIFIED.
2. Для перехода от предложения замены к сохранению в проекте нужна транзакция, пересчёт раскладки и подтверждение пользователя; текущий API только предлагает изменения.
3. Не реализована реалистичная визуализация конкретных серий и проверка лицензий изображений.
4. Не проверены механические зазоры, тепловой режим, клеммы, токи КЗ, селективность и нормативное соответствие.
5. Сверка с Python v4.14 не проведена из-за отсутствия подтверждённого полного исходного архива.

## Критерии дальнейшей работы
- Верифицировать минимум два конкретных артикула и паспорта производителя, отдельно ширину/высоту/глубину и допустимое крепление.
- Сделать обратимую транзакцию выбора артикула, пересчитывать DIN-раскладку и явно отмечать конфликты.
- Подключить качественные изображения только с разрешённым использованием; иначе нейтральный фасад.
- Подтвердить CI последнего коммита и браузерный сценарий до слияния.

## Следующий блок: контроль расчётной полноты
Добавлен `project-calculation-coverage-v1.js`, включён в общий инженерный отчёт. Для каждой линии проверяется наличие заявленных Ib, Iz, выбранного артикула, исходных данных маршрута/КЗ и записи о рассмотрении расчётов. Несоответствие заявленных Ib/In/Iz помечается BLOCKED. Это **проверка полноты и арифметической согласованности**, а не выполнение нормативного расчёта. Наличие полей само по себе не доказывает правильность токов или методик. Для реального проектирования остаются расчёты применимости кабеля, КЗ, отключения, селективности и теплового режима с первичными источниками.

## Этап: детерминированный черновой план щита
Добавлен `draft-board-plan-v1.js`: без изменения пользовательского проекта формирует последовательное размещение устройств на рейках, не разделяет аппараты между рейками, обнаруживает нехватку мест, дубли ID и расхождения ширины с выбранным каталожным артикулом. Включён в `engineering-gate-v1.js` и браузерную диагностику. Это предварительная раскладка; не проверяет нагрев, расстояния, монтажные аксессуары и электрическую безопасность. Следующая задача — согласованное применение предложенной раскладки и полноценная методика выбора аппаратов и проводников.

## Этап: кандидаты защитной автоматики
Добавлен `protective-device-shortlist-v1.js` с проектным аудитом: проверяет только явные Ib, Iz, Iкз, фазность и паспортные In/Icn/полюса доступных MCB. Отсутствующие данные переводят кандидатов в INCOMPLETE; несоответствия — REJECTED; потенциальные кандидаты не являются нормативным подбором. Не подтверждены I2, характеристика отключения, система заземления, петля, селективность, нагрев, резервирование, корректность Icn/Icu/Ics для конкретной системы и достоверность паспортных данных. Не выбирать оборудование автоматически без этих проверок.

## Оптимизация качества: этап проверки выбора защиты
Вместо наращивания числа тестов без цели усилены проверки двух рисков: (1) внутренний ключ каталога нельзя подменять заводским артикулом при сопоставлении; (2) отсутствие Ib/Iz/Iкз никогда не создаёт статус потенциального выбора. Парсер положительных токов вынесен в одну функцию; проектный аудит принимает тестовый каталог явным аргументом. Для выбранного аппарата с неполными данными добавлен отдельный код `SELECTED_ARTICLE_EVIDENCE_INCOMPLETE`. Покрыты граничные и некорректные вводы. Это не подтверждение применимости Icn, кабеля или защитного отключения.
